# 学习路径与星图管理

本次实现覆盖学习路径、公共知识星图管理及其所需的学习评价闭环。需求依据为仓库中的《遥感通》项目解决方案第四章修订版；原说明书及附件保持不变。

## 启用

1. 在 `backend/` 执行 `uv sync`，重启后端。启动过程创建新增表，不改写旧表结构。
2. 首次演示执行 `uv run python -m app.seed`。六道示例客观题覆盖三个基础节点，每个节点两题。图谱一旦由管理员修改，种子脚本不再覆盖其节点、关系、内容或题库。
3. 注册一个账号，再执行 `uv run python -m app.admin 实际邮箱`。重新登录后访问 `/knowledge-management`。撤销使用同命令加 `--revoke`。
4. 在管理页为实际学习节点配置评价任务、参考依据及难度。选择题填写选项和正确答案；解释题填写评分标准、参考答案及来源。
5. 在 `/path-planning` 设置目标和每日时间，在节点学习页提交任务。

普通注册只创建普通用户。`Administrator` 独立关联已有 `User`，不复制密码；服务器检查管理员表，不能靠客户端角色或 JWT 中的 `admin` 字样提升权限。此变更不会自动提升任何现有账号。

## 图谱管理规则

- 支持方向、课程、概念、方法、工具五种节点；方向和课程可通过包含关系组织下层知识点。
- 前置依赖表示先学 A 再学 B。包含表示 A 下含 B；应用与关联用于表达联系，不单独触发解锁。
- 课程或方向间的先修约束展开到其包含的叶节点。保存关系时同时检查原始图与展开后的依赖，拒绝自环、重复关系和循环依赖。
- 每次修改携带 `expectedRevision`。版本过期返回 409，刷新并重新编辑后才能保存；成功操作增加版本并记入操作记录。
- 有关系、学习记录或当前目标引用的节点不能删除。任务移除后，历史作答保存的题目快照仍可用于重试和回放。
- 管理页可新增、修改、删除节点和关系；任务支持新增及移除。调整题目时移除旧任务、创建新任务，保留原始评价依据。

## 路径规则 adaptive-v1

路径界面使用 `entries[].prerequisites` 绘制待学依赖子图：这些关系来自后端对包含层级展开后的先修依赖，并已排除满足的前置内容。只连接当前待学集合中的真实前置关系，不把排序相邻项直接相连。图按依赖深度分层，展示分支与汇合，使用 `nextNodeId` 突出推荐下一步；无依赖的可学节点并列展示。推荐顺序仍由后端决定，前端布局不改变调度与解锁。窄屏保留分支结构，在图内滚动查看；首页预览去掉相邻箭头。节点详情显示实际前置要求、预计时间与配套练习。掌握度、置信度等仍用于后端决策，但不在路径图或详情弹窗中展示。

驾驶舱预览和完整路线共享 `['path', 'plan']` 数据。保存目标、重新规划后同步刷新相关查询；学习事件沿用现有路径失效刷新机制。弹窗只保存节点 ID，从最新路线取详情，避免完成或重排后继续操作旧节点。历史回放使用冻结的路线数据，并禁用学习操作。

先将目标展开为叶节点，再补齐全部先修闭包。只有掌握度至少 80、置信度至少 60 且上游先修均达标，节点才满足解锁条件。未满足的后续节点展示在计划中，但不能提交其评价任务。

候选排序综合目标相关性、掌握差距、错误标签、学习连续性、近期重复和跳过偏好；同分使用稳定顺序。当前可执行参数为目标权重 5、差距权重 3、错误权重 2、连续性权重 1、重复惩罚 0.5、跳过惩罚 3。跳过只影响优先级，必要先修仍保留。

根据掌握情况选择基础、分步或综合难度，优先近期未做且可放进每日预算的任务。阅读时间可跨天拆分，单项评价任务完整安排在一天内；预算容不下现有任务时，页面提示增加时间或补充短任务。时间为规划估计，并非完成保证。

首次有效评价建立掌握度基线；后续掌握度为 `0.7 × 原掌握度 + 0.3 × 本次有效分数`。较强提示的有效分数乘以 0.9。置信度按不同任务数每道增加 30，上限 95；近七天不足两道不同任务的有效评价时，上限为 40。重复同一道题不能单靠次数解锁，过期证据会引入复习安排。

这些是明确版本化的工程初始参数，说明书中的待校准项不能当作已经实验证实的学习效果。

## 事件、评价和回放

`LearningEvent` 追加保存阅读、提示、接受建议、跳过和作答。`requestId` 在同一用户内唯一：相同请求重试返回已有事件，不重复计分；同编号的不同内容返回 409。

客观题由服务器核对答案。解释题将冻结的任务、参考材料和评分标准交给模型；服务器验证评分结构及范围，再按确定规则更新状态。模型缺失、调用失败或输出不合格时，作答保持待评价，允许重试，不产生演示分数。模型测试使用受控响应，不能替代生产服务的可用性验证。

原始事件、`LearningEvaluation` 和 `StateChange` 分表保存。同一事件只允许一份评价和状态变化。用户行锁串行化同一人的写入；模型调用期间释放数据库事务，取得评价后再加锁检查是否已被其他重试处理。

目标、图谱和证据变化时按规则重新计算。只有路径顺序、任务、难度、时间安排、解锁状态等有实际变化才保存新版本。历史版本保存图谱、目标、状态、规则及事件/评价编号等冻结输入，读取历史时重新计算验证；不会覆盖当前路径，也不会向学习者暴露题库答案。不同用户不能访问彼此的版本或事件。

知识星图、节点页与驾驶舱按新学习证据显示掌握情况。旧手动完成记录只作为历史保留，不能替代新的评价证据。

## 验收

```powershell
# backend/
uv run pytest
uv run ruff check app tests

# frontend/
pnpm.cmd test
pnpm.cmd lint
pnpm.cmd build
```

后端测试使用独立 SQLite 内存数据库，覆盖管理员身份、图谱 CRUD 与并发版本、循环依赖、重复计分防护、弱证据、主观评价失败/重试、补学与预算、依赖变更、历史隔离和回放；不连接开发 MySQL。生产数据库的行锁由 MySQL 提供，SQLite 测试不代表完成了 MySQL 并发压力验证。

手动验收可创建 A → B → C，给 A 配两道题：普通用户访问管理接口应返回 403；选择 C 后应先推荐 A；只阅读或只做一道题不能解锁 B；两道不同题近期均答对后应推荐 B；反向添加 C → A 应被拒绝。查看历史路径后，返回当前路径应保持最新状态。

本次未实现说明书中的独立遥感影像配准质量验收流水线、完整 RAG 资料库或离线批量事件同步；它们仍属于后续模块。当前任务评价类型为选择题和解释题，题库内容需按课程继续完善。
